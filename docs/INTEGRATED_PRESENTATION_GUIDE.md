#### 📝 Slide 10. Redis Sorted Set (ZSET) 기반 우선순위 제어 명령 큐 구축
* **슬라이드 내용**:
  - **자료구조**: 기존 FIFO 리스트에서 Sorted Set(`zadd`/`zpopmax`)으로 전환
  - **태스크 우선순위화**:
    * P1 (회전/배출/합적직송): **Score 100**
    * P1.5 (A구역 빈작업대 공급): **Score 90**
    * P2 (포장 공급/이송): **Score 80**
    * P3 (B구역 Look-ahead 사전이송): **Score 50**
  - **안정성**: 동적 `uuid` 부여를 통한 중복 태스크 진입 차단
* **발표 스크립트 (Script)**:
  > "기존의 선입선출(FIFO) 큐에서는 긴급한 회전이나 배출 명령이 뒤로 밀려 병목이 심했습니다. 이를 해결하기 위해 Redis Sorted Set(ZSET)을 명령어 큐로 전환하여 작업 유형에 따라 스코어 기반 우선순위를 차등 배정했습니다. 중복 실행을 막기 위해 각 명령엔 고유 UUID를 탑재해 멱등성을 보장했습니다."

#### 📝 Slide 25. Thread-Safe 데이터베이스 락 및 커넥션 풀 구축
* **슬라이드 내용**:
  - **문제점**: ROS 2 멀티스레드 Executor 내부에서 병렬 콜백들이 단일 PostgreSQL 커넥션 자원을 동시 공유하며 트랜잭션 충돌 및 커서 무결성 오류 유발
  - **해결 방안**: 
    * 파이썬 재진입 락인 `threading.RLock()` 기반 `self.pg_lock` 뮤텍스를 노드 내부 트랜잭션 전 구간에 설계
    * `ThreadedConnectionPool`을 도입하여 병렬 DB 커넥션 요청 지연 전면 제거
* **발표 스크립트 (Script)**:
  > "대량의 로봇이 실시간 데이터를 쓸 때, 멀티스레드로 기동되는 관제탑 노드가 데이터베이스 커서를 공유 사용하면서 충돌 에러가 발생했습니다. 이를 방지하고자 중첩 호출이 안전하게 허용되는 '재진입 락(RLock)' 기반의 뮤텍스 처리를 수행하여 트랜잭션들의 병렬 안전성을 충실히 다졌고, 스레드 전용 풀러를 구축해 쿼리 성능을 한 단계 높였습니다."
