## 📌 Slide 02. 전체 개발 환경 및 기술 명세 (1:00 ~ 2:00)

저희 시스템은 실시간 분산 로봇 제어와 영속적이고 안전한 물류 트랜잭션을 동시에 만족시키기 위해 '하이브리드 데이터 플랫폼'을 선택했습니다.

OS로는 Ubuntu 22.04, 미들웨어는 ROS 2 Humble을 활용하고 통신 RMW로는 Cyclone DDS를 채택해 다중 로봇 간의 실시간 비동기 이벤트를 바인딩했습니다. 특히, 정합성이 엄격해야 하는 물류 패키지 및 스팟 상태는 관계형 DB인 PostgreSQL 15에서 트랜잭션으로 보장하고, 고속으로 실시간 변화하는 AMR의 기기 위치 및 우선순위 명령어는 인메모리 스토리지인 Redis 7.0에서 수용하게 만들어 백엔드의 IO 병목을 원천 해소했습니다.

## 📌 Slide 05. PostgreSQL 데이터베이스 스키마 정규화 (2:00 ~ 3:00)

초기 데이터 설계에서는 작업대(Workstation) 테이블 내부에 'slot_1'부터 'slot_8'이라는 개별 컬럼을 하드코딩 형태로 만들어 보관했습니다. 이는 빈번한 컬럼 업데이트 부하를 일으키고, 슬롯 수량이 변할 때마다 스키마를 고쳐야 하는 유연성 한계가 있었습니다.

저희는 과감하게 workstations 내의 슬롯 컬럼들을 삭제하고, `packages` 테이블에 `workstation_id`와 `slot_number` 외래키를 주어 1대 N 관계로 스키마 정규화를 실시했습니다. 이 정규화 설계 덕분에 작업대 상태 변경에 따른 불필요한 IO 부하를 차단하고, 단순 SQL JOIN 쿼리만으로 실시간 점유 슬롯 수량과 패키지의 정확한 위치를 동적으로 추출할 수 있게 되었습니다.

> 🔄 **→ 다음 슬라이드**: "이렇게 잘 정의된 데이터베이스 테이블의 엔티티들과 물리 세계의 로봇 및 사물들을 어떻게 매핑했는지 설명드리겠습니다."

## 📌 Slide 06. QR ID 통합 물류 매핑 체계 구축 (3:00 ~ 4:00)

물리 공간의 로봇 센서 인식 데이터와 가상 DB의 논리 엔티티를 끊김 없이 바인딩하기 위해 고유 식별자 매핑 체계를 단일화했습니다.

기존의 파편화된 식별자들을 DB의 `robots`, `workstations`, `packages` 테이블 내에 `qr_id` 고유 컬럼으로 통일 추가했습니다. 이를 통해 로봇 비전 카메라가 특정 사물의 QR 코드를 스캔하는 즉시, 중앙 관제 노드에서는 추가 연산 없이 이 QR ID로 WMS 데이터베이스를 다이렉트로 쿼리해 유효성을 검증하고, 제어 명령을 호출할 수 있는 실시간 물리-논리 매핑 루프를 확립했습니다.

> 🔄 **→ 다음 슬라이드**: "이처럼 데이터 인프라가 확보된 후, 다수 AMR에게 명령을 내리고 분산 처리하기 위한 대기열 스케줄링 방식을 개선했습니다."

## 📌 Slide 09. Redis ZSET 기반 우선순위 제어 명령 큐 (4:00 ~ 5:00)

기존 시스템은 일반적인 FIFO(선입선출) 큐를 사용했습니다. 그러나 물류 작업 도중 긴급한 회전이나 배출 명령이 뒤로 밀리며 심각한 병목이 유발되곤 했습니다.

이를 극복하기 위해 명령어 대기열을 Redis Sorted Set(ZSET)으로 전면 교체했습니다. 작업 유형별로 가중치 스코어를 부여하여, 회전이나 긴급 배출 명령에는 최고점인 100점을, Look-ahead 사전이송 태스크에는 50점을 부과하여 관제 스케줄러가 항상 최우선 작업부터 꺼내 가도록 설계했습니다. 중복 명령 삽입을 원천 차단하기 위해 각 태스크에 고유 UUID를 발급하여 멱등성 보장도 강화했습니다.

> 🔄 **→ 다음 슬라이드**: "이러한 명령 우선순위에 따라, AMR과 로봇 팔이 한정된 공간에서 부딪치지 않고 작업할 수 있도록 설계한 안전 알고리즘입니다."

## 📌 Slide 12. JIT 인터로킹 물리 충돌 방지 시스템 (5:00 ~ 6:00)

시뮬레이션 구동 시, AMR이 작업대를 도킹 해제하여 회전하는 중에도 로봇 팔이 이를 감지하지 못하고 상자를 계속 떨어뜨려 물리적 낙하와 그래픽 충돌이 발생하는 병목이 있었습니다.

저희는 관제탑에서 실시간 기동 상태를 추적해 로봇 암 노드에 '일시정지 표준 토픽(pause_status = True)'을 발행하는 JIT 인터로킹 프로토콜을 구현했습니다. AMR의 기동(이송/회전) 동안 로봇 팔은 동작을 일시 중단하며 안전 대기를 유지하고, AMR의 액션이 안전하게 완료되면 Resume 신호를 주어 공정을 즉시 재개시키는 논리 인터로킹 구조를 통해 물리 충돌률을 완벽히 0%로 통제했습니다.

> 🔄 **→ 다음 슬라이드**: "동시에 로봇 팔이 멈춰 서서 놀게 되는 유휴 시간을 방지하기 위해 이중 버퍼 구조를 추가했습니다."

## 📌 Slide 13. A/B 이중 버퍼 배치 및 Look-ahead 사전 이송 (6:00 ~ 7:00)

아무리 인터로킹이 안전하더라도, 작업대가 꽉 차서 회수되고 새 작업대가 올 때까지 로봇 팔이 마냥 기다려야 한다면 공정 효율이 급격히 저하됩니다.

이를 해결하기 위해 각 라인에 Active 구역인 A와 예비 구역인 B의 이중 버퍼를 설계했습니다. 그리고 A구역 작업대에 상자가 3개 적재되는 시점을 트리거로 잡는 'Look-ahead' 타이머를 도입했습니다. B구역으로 빈 작업대를 미리 호출해 대기시킴으로써, A구역의 완충 작업대가 회수되는 즉시 B구역의 작업대를 사용하게 만들었습니다. 이를 통해 교체 주기에 발생하는 로봇 팔의 유휴(Idle) 대기 시간을 기존 45초에서 3초 미만으로 비약적으로 단축했습니다.

> 🔄 **→ 다음 슬라이드**: "이어서 가상 시뮬레이션 환경에서 맞닥뜨린 치명적인 성능 저하와 이를 극복한 GPU 리소스 최적화 내역입니다."

## 📌 Slide 17. OpenUSD 바닥 QR 격자 인스턴싱 최적화 (7:00 ~ 8:00)

물류창고 내부에서 AMR의 자율주행을 지원하기 위해 1.5m 간격으로 143개의 고해상도 QR 메쉬 마커를 배치해야 했습니다. 그러나 143개의 독립된 Quad Mesh와 텍스처를 GPU에 개별 드로우콜하면서 Isaac Sim 구동 프레임이 5 FPS 미만으로 떨어져 정상 구동이 불가능했습니다.

저희는 Pixar OpenUSD의 핵심 경량화 기법인 '인스턴싱(Instancing)' 기술을 자체 스크립트에 이식했습니다. 단 1개의 프로토타입 메쉬만 VRAM에 로드하고, 나머지 143개 좌표에는 `SetInstanceable(True)`을 활성화한 내부 참조 노드로 배치했습니다. 그 결과 USD 파일 크기를 수십 MB에서 372KB로 초경량화하고, 렌더링 성능을 60 FPS 이상으로 끌어올리는 극적인 성과를 달성했습니다.

> 🔄 **→ 다음 슬라이드**: "다음은 모니터링 단의 부하 또한 동일한 관점으로 경량화시킨 대시보드 최적화 사례입니다."

## 📌 Slide 20. 2D 실시간 웹 대시보드 렌더링 성능 최적화 (8:00 ~ 9:00)

실시간 2D 모니터링 웹 대시보드를 구축할 때, 720개의 바닥 격자 구역을 나타내기 위해 수백 개의 HTML div 요소를 브라우저에 배치하고 데이터 변경 시마다 매초 DOM 렌더링을 유도했습니다. 이로 인해 브라우저 CPU 점유율이 95% 이상으로 치솟아 화면이 버벅였습니다.

저희는 화면 전체의 바닥 격자를 표기하던 HTML div 요소들을 전면 삭제하고, CSS linear gradient 배경 기법을 도입하여 레이아웃을 극적으로 단일화했습니다. 실시간 상태가 변하는 극소수의 위치 정보(31개 포인트)만 절대 좌표(absolute positioning)를 활용해 레이어로 가볍게 점만 찍어 렌더링하도록 렌더링 파이프라인을 교체했습니다. 이로써 DOM 연산 오버헤드를 95% 이상 감축하고 브라우저 부하를 5% 미만으로 해결했습니다.

> 🔄 **→ 다음 슬라이드**: "마지막으로 본 프로젝트를 통해 달성한 종합 기술 성과를 요약하며 발표를 마치겠습니다."
